# 重做 ADOFAI 与喵斯应用风格成绩图

## 改动原因

上一版固定成绩图没有严格套用已有 Phigros“应用风格”：出现了额外装饰线、通用白卡、右侧指标栏和错误的信息顺序；预览与导出又分成内联 HTML、临时文件两条链路，导致预览空白和截图高度不稳定。ADOFAI 的远程头像与卡片封面也没有在 HTML 创建前完成本地化，导出时可能缺图。

## 具体实现

- 抽取无游戏 ID 的 `ApplicationBestImageCardPresentation`、应用风格三列卡片渲染器、卡片 CSS 和画布 runtime；Phigros 应用风格模板改走公共卡片/CSS/runtime，原头部和视觉参数不变。
- 删除固定成绩图的顶部双色线、通用白卡、榜单序号、独立条数、右侧 Impact/Rating 栏和文档式标题；页面只保留浅蓝灰画布、左上身份、居中渐隐分隔线、三列难度色卡片及既有底部署名。
- 喵斯按 `ID/标题 → ACC → 定数 → Rating → 评价/成就/排名 → 角色/精灵/游玩端` 映射；ACC 与所有徽章复用现有渐变、tone 和中性徽章，卡面只使用 `museDashLevelTheme`。
- ADOFAI 按 `ID/标题 → Score → 难度 → Impact → 标签图标 → XACC/倍速/WF/PP` 映射；标签只输出已存在并成功本地化的 18px 图标，卡面使用 `tufDifficultyVisual`、既有特殊难度渐变或深灰未知回退。
- 抽取既有 expo-image 磁盘缓存转 data URI 的公共素材加载器，保留中二原函数薄包装。Muse 封面、TUF 头像/视频封面/难度图标/标签图标均在 HTML 创建前本地化。
- TUF 头像继续统一使用 `resolveTufAvatarUrl` 的四级优先级，下载或解析失败直接嵌入本地 ADOFAI 图标；封面按视频图片代理、原图、难度图标、本地图标逐卡回退。
- TUF 批量封面查询抽出并复用 `tufVideoDetailsQueryOptions`，保持原 Provider、React Query key 和缓存时长。
- `FixedBestImageScreen` 的预览与导出改用同一份 `prepareBestImageWebViewSources` 本地文件 source，并复用 ready/height/runtime 握手、实测高度、320ms 布局稳定等待、截图、权限、保存和清理路径；本地 HTML 创建失败提供明确重试入口。

## 期望输出

- ADOFAI 标题严格为 `Top${实际数量}`，喵斯严格为 `Best${实际数量}`；标题居中并保留两侧既有分隔线。
- ADOFAI 左上始终显示头像、玩家名和 Rating；喵斯左上只显示玩家名和 Rating。
- 1080、1440、2160 三档均输出三列完整卡片、全部成绩和底部署名，无横向溢出；预览与相册导出内容一致。
- Phigros 应用风格在抽取公共实现前后视觉差异为 0。
