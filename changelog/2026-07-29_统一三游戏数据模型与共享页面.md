# 统一三游戏数据模型与共享页面

## 改动原因

舞萌 DX、Phigros 和中二节奏原先分别维护总览、最佳、成绩、曲库和歌曲详情，导致相同能力的布局、筛选、空态与本地曲库行为逐渐分叉。需要建立统一应用层数据契约，把游戏差异收敛到适配器、动作和资源注册层。

## 具体实现

- 新增 `rranker-game-model/v1` Zod schema，分离 `GameManifestV1` 与 `GameDataDocumentV1`，并校验标签角色、样式、筛选器、白名单动作、资源引用和跨文档引用。
- 新增舞萌、Phigros、中二和测试游戏 Manifest 及适配器，统一输出账号、歌曲、谱面、成绩、最佳栏目、来源状态和页面动态数据。
- 新增共享总览、最佳、成绩、曲库、歌曲详情页面，以及共享标签、歌曲卡、成绩卡、筛选器和资源组件；页面不再按游戏分支渲染。
- 将 U·TA·GE、BUDDY 左右物量、Phigros XING、中二 WORLD'S END、收藏品、谱面搜索和同步动作映射为统一标签、栏目或动作。
- 将筛选状态统一为按游戏、页面和筛选器隔离的声明式状态，支持标签、列表、范围、搜索、重置和无结果空态。
- 将个人曲库谱面主键统一为 `chartId`；SQLite schema 升到 5，备份格式升到 v4，并支持导入 v1–v3 旧谱面键。
- 新增中文契约文档、合法/非法 JSON 示例、schema/适配器/筛选测试，并更新共享页面与数据迁移回归测试。

## 期望输出

- 三游戏五个核心页面使用同一套页面模型和共享组件。
- Manifest 与 Document 均能 JSON 序列化并通过严格校验，错误配置在开发环境可定位、生产环境安全回退。
- 三游戏特殊能力和现有同步、上传、收藏、练习、本地标签、外部搜索能力保持可用。
- 本地曲库、旧备份导入和新备份往返符合 schema 5 / v4 约定。
- Android 与 iOS 均能完成生产 bundle。
