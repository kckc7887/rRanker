# 修复谱面确认全屏方向枚举错误

## 改动原因

舞萌谱面确认播放器进入全屏后，iOS 反复弹出 `[RNScreens] Unsupported orientation mask` 报错窗口。

经核对 `react-native-screens` iOS 源码与上游 issue（[software-mansion/react-native-screens#3473](https://github.com/software-mansion/react-native-screens/issues/3473)），项目使用的 `react-native-screens@~4.16.0` 在 `ios/conversion/RNSConversions.mm` 第 46 行存在枚举常量拼写错误：

```mm
case UIInterfaceOrientationLandscapeRight:        // 实际枚举值为 4（UIInterfaceOrientation）
  return RNSOrientationLandscapeRight;
```

应为 `UIInterfaceOrientationMaskLandscapeRight`（枚举值为 16）。当 `Stack.Screen options.orientation` 设置为 `'landscape_right'` 时，正向转换得到 `UIInterfaceOrientationMaskLandscapeRight`（值 16）；`evaluateOrientation` 反向转换时，switch 在 mask=16 上找不到匹配 case，落入 default 分支触发 `RCTLogError(@"[RNScreens] Unsupported orientation mask")`。iOS 进入全屏后每次旋转、状态栏更新、布局变化都会重新查询 `supportedInterfaceOrientations`，导致错误反复弹出。

该问题在 react-native-screens 4.18.0 后由官方 PR [#3474](https://github.com/software-mansion/react-native-screens/pull/3474) 修复，但本项目依赖版本较早，未包含此修复。`'landscape_left'` 对应的 case 使用了正确的 `UIInterfaceOrientationMaskLandscapeLeft`，不受此 bug 影响。

## 具体实现

- 将 `app/songs/chart-preview.tsx` 中 `Stack.Screen` 的 `orientation` 全屏值由 `'landscape_right'` 改为 `'landscape_left'`，规避 `RNSConversions.mm` 反向转换的枚举拼写错误。
- 同步更新 `tests/maimai-chart-preview-screen.test.tsx` 中全屏后期望值断言为 `'landscape_left'`。
- 不修改 `react-native-screens` 依赖版本，不修改应用版本号，不修改 Info.plist、`app.json` 与播放器构建产物。
- 谱面播放区为圆形判定区，左右横屏方向仅是设备镜像，对播放器视觉与交互无影响；用户如需调整可使用播放器内置的镜像设置。

## 期望输出

- 舞萌谱面确认播放器进入全屏后不再弹出 `[RNScreens] Unsupported orientation mask` 报错窗口。
- 全屏仍锁定为单一横屏方向，退出全屏后恢复 `portrait_up`。
- 既有 lint、typecheck、Vitest 与 Jest 套件全部通过。
