# 喵斯快跑接入 musedash.moe 社区查分

## 改动原因

- 用户要求接入 Muse Dash（喵斯快跑）作为新游戏，数据源为 musedash.moe 社区公开 API（https://api.musedash.moe），无需登录、无鉴权。
- 遵循新游戏接入规范：独立 Provider DTO/Zod Schema/缓存快照、实现泛型 `GameContentAdapter`、复用共享页面与 `components/game-content/` 基础组件、不得修改共享组件枚举游戏、不改变既有游戏数据与存储。

## 具体实现

- **数据层（阶段 1）**
  - 新建 `domain/muse-dash.ts`：上游契约全部 Zod Schema（`/albums` 专辑与歌曲、`/player/:id` 玩家与成绩、`/diffdiff` 定数、`/ce` 角色/精灵名称表、`/search` 搜索结果），扩展类型 `MuseDashSongExtension` / `MuseDashChartExtension` / `MuseDashScoreExtension`（保留原始字段与计算语义），独立 `musedash:` 命名空间缓存快照与 schema 版本、资源 key，以及名称/定数解析 helper（ChineseS 优先、`museDashDiffdiffMap`、`museDashSongsByUid`、角色/精灵按 uid 数组索引解析）。
  - 新建 `providers/muse-dash-provider.ts`：仿 TUF 的注入 fetcher + 12s 超时 + 429/5xx 重试 + Zod 解析失败抛 `ProviderError('upstream_schema')`；方法 `searchPlayers` / `getPlayer` / `getAlbums` / `getCe` / `getDiffdiff`。
  - 新建 `services/muse-dash-cache.ts`：`MuseDashCache` 读写 `resource_snapshots`（albums/ce/diffdiff 全局资源 + 按 userId 的玩家缓存），`clearPlayer` 解绑清理，player/albums/ce/diffdiff 各自 in-flight 去重。
  - 新建 `storage/musedash-account-store.ts`：KV 账号档案（仅 userId/displayName，版本化去重）。
- **注册分发点（阶段 2）**：`game-bind-options.ts` 新增 `GameId 'musedash'` 与 `ProviderId 'musedash-moe'`（`public-player` 绑定）；`models.ts` `DataSourceKind` 加 `'musedash'`；`game-profile.ts` 注册「喵斯快跑」档案（Rating / Best 30）；`game-data.ts` `GamePayload` 加 `kind: 'musedash'`；`bound-account.ts` 加 `createMuseDashBoundAccount`（`musedash:musedash-moe:{userId}`）与解析函数；`game-toolbox.ts` 空工具箱；`user-library.ts` `GameIdSchema`/`KNOWN_GAME_IDS` 登记并让 `normalizeLibrarySongId` 原样保留 `0-48` 类 uid；`pinned-tool-preferences.ts` / `arcade-finder-preferences.ts` / `game-storage-adapters.ts`（`musedash:` 前缀归属 + adapter）/ `storage-usage.ts`（粉色 `#EC4899` 段）注册；`session-store.ts` `providersForAccount` 与 `clearSession` 保留分支。
- **适配器与展示（阶段 3）**：`features/game-content/adapters.ts` 新增 `museDashContentAdapter`（歌曲 5 档难度映射、缺失档跳过、`libraryRef` 为空、谱师/定数 join、成绩 join 曲库与角色/精灵名称）与 `presentMuseDashScore` / `presentMuseDashSong` / `presentMuseDashChart` / `formatMuseDashAcc` / `formatMuseDashScore`。
- **Hook、页面与路由（阶段 4）**：新建 `hooks/use-muse-dash.ts`（5 个查询 hook 全部 `cacheFirstLoad` + `['musedash',...]` queryKey）、`screens/MuseDashScreens.tsx`（Best 30 按社区 Rating sum 降序、成绩本地平台/排序/搜索筛选、曲库难度档/搜索筛选、歌曲详情页含难度卡与未游玩提示）、`components/musedash/`（`MuseDashScoreCard` / `MuseDashSongRow` / `MuseDashFilterBar` / `MuseDashOverviewDetails` 含粉色 `MUSE_DASH_RATING_THEME`）与 `components/MuseDashPlayerPickerSheet.tsx`（昵称搜索绑定弹层）；`use-game-data.ts` 四处分支、总览/最佳/成绩/曲库/歌曲详情五处路由分支、`app/_layout.tsx` 账号恢复、`GameAccountsScreen.tsx` 绑定/解绑流程；图标从 musedash.moe 站点获取 `apple-touch-icon` 生成 `musedash.png` 与 `musedash-moe.png`（256×256，后续可替换为官方素材）。
- **测试（阶段 5）**：`tests/fixtures/musedash/` 五个脱敏 fixture；新增 provider（URL/重试/畸形响应）、cache（key/快照/解绑清理/in-flight）、account-store、content-adapter（歌曲/谱面/成绩映射，覆盖缺失难度档、join 缺失、满成绩、角色精灵越界）、screens（jest）、overview-public（jest）、live-smoke（`MUSE_DASH_LIVE_SMOKE=1` 门控）；共享断言更新（storage-management、pinned-tool-preferences、toolbox-screen、user-library、m3-settings）；新增 `future-game-render-contract.test.tsx` 证明共享 `GameScoreCard` / `GameSongRow` / `BestListPage` / `GameChartResultCard` / `GameNoteTable` 无需修改即可渲染虚构游戏。
