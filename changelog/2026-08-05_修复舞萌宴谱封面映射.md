# 修复舞萌宴谱封面映射规则

## 改动原因

舞萌宴谱部分歌曲无封面（歌曲详情、搜索、曲库的 SongCover 加载 404），但原曲封面存在。经全量抓取 LXNS 曲库（1322 首，60 张宴谱）验证，宴谱 id 编码为「前缀段 ×10000 + 原曲 id」，前缀段从 10 到 16（同曲多版本联谱，如 Garakuta Doll Play 的 100227/110227/120227/130227/140227），原曲 id 恒为后四位；LXNS 曲库中不存在任何五位 id，也不存在「100000 + 五位原曲」的宴谱。原实现按 `id - 100000` 推断原曲，11 及以上前缀段会得到不存在的五位 id 导致封面 404；`mapCoverId` 的 `>= 110000` 分支也漏掉了 12–16 前缀段。

## 具体实现

- `src/domain/catalog.ts` `originalSongIdForUtage`：宴谱 id（> 100000）改为 `numericId % 10000` 取后四位。
- `src/domain/rating.ts` `mapCoverId`：`>= 100000` 改为 `songId % 10000`，覆盖全部 10–16 前缀段；`10001–19999` 水鱼偏移分支保留。
- 测试更新：`catalog.test.ts` 将 110123 的期望原曲 id 由 `10123` 改为 `123`、封面 URL 同步更新，新增 12 前缀用例（120227 → 227）；`rating.test.ts` 新增 `mapCoverId(120227) = 227`。

## 期望输出

- 11 前缀（如 110114→114）与 12–16 前缀（如 120227→227）宴谱的封面 URL 全部回落到真实原曲封面，不再 404。
- 同一原曲多张宴谱共享同一张原曲封面；10 前缀宴谱（100123→123）、四位及水鱼五位 id 的既有映射不变。

## 实际输出

- lint 0 error、typecheck 通过；Vitest 107 文件 677 用例、Jest 36 套件 192 用例全部通过，其中更新与新增的宴谱映射断言按上述期望通过。
