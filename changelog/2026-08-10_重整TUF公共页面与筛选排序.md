# 重整 TUF 公共页面与筛选排序

## 改动原因

冰与火之舞的 TUF 总览、成绩和曲库虽然已经接入共享列表骨架，但总览仍使用独立英雄卡布局，成绩页筛选器也与应用内其它游戏的信息层级不一致；曲库缺少服务端排序和难度筛选，面对庞大的社区内容时难以快速缩小范围。

## 具体实现

- 总览页改用公共的玩家标题、数据来源状态和 `DxRatingCard` 结构，以冰/火渐变作为 TUF 的主题识别；公开资料卡继续展示 General Score、PP Score、平均 XACC、Universal Pass、最高难度和世界首杀，世界排名与过关数收拢到主评分卡说明。
- 成绩页继续复用 `RecordsListPage` 与 `TufScoreCard`，新增 350ms 防抖关键词筛选、`score / speed / date / xacc / difficulty / impact` 服务端排序、升降序和每关最佳设置；筛选面板支持收起与重置。
- 曲库页继续复用 `CatalogListPage` 与 `TufSongRow`，新增最近更新、难度、通关人数、通关次数、喜欢、基准分、BPM、物量和时长的服务端排序，支持升降序、P/G/U 区间与动态特殊难度筛选。
- 扩展 TUF Provider 与查询类型，严格保留上游 `query`、`sort`、`pguRange`、`specialDifficulties` 语义；难度列表使用短生命周期 React Query 内存缓存，不写入 SQLite。
- 成绩和关卡分页结果按上游 ID 去重；查询 key 包含全部筛选状态，筛选变化后从 offset 0 建立新查询，不预取后续页。
- 补充 Provider 参数契约、成绩筛选、曲库排序/难度筛选、分页去重、公共总览和空载荷防护测试；未向共享组件加入 `adofai` 分支。

## 期望输出

- TUF 三个主页面与应用公共页面保持一致的标题、卡片、列表与筛选层级，同时保留冰与火的主题辨识。
- 成绩和曲库只请求当前筛选条件与当前页，用户可按关键词、排序和难度快速定位社区内容。
- 既有游戏页面、共享组件契约、存储 Schema、版本号和 TUF 无凭据/无落盘约束不发生变化。
