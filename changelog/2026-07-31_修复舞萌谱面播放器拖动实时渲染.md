# 修复舞萌谱面播放器拖动实时渲染

## 改动原因

舞萌谱面确认播放器在 Expo Go 中存在多处拖动相关 bug：

1. 非全屏拖动进度条时谱面定格，无法继续播放，暂停播放键点击无效，原本拖动时实时渲染的能力丢失。
2. 全屏进度条无法连续拖动，只能点击跳转。
3. 移动设备上拖动被系统中断（多指、来电、通知等）后，`isDragging` 状态卡住，后续播放键点击被 pointermove 拖动逻辑干扰，导致"暂停键点击无效"。

经核查 `apps/mobile/src/features/maimai-chart-preview/webview-player/main.ts`，根因为：

- `seekToPosition` 只更新 playhead 和 timeLabel，未调用 `renderer.renderFrame` 与 `updateOverlayDom`，导致拖动时画面不实时变化。
- `fsTimelineHost` 的 `pointerdown` 未设置 `isDragging=true`、未保存 `wasPlaying`、未调用 `pausePlayback()`，所以 document 上的 pointermove/pointerup 不会处理全屏进度条的拖动。
- `document` 的 `pointermove` 只用 `timelineHost` 的 rect，全屏时应使用 `fsTimelineHost` 的 rect。
- 缺 `pointercancel` 监听，系统中断时 `isDragging` 不会被重置。

## 具体实现

- `main.ts` `seekToPosition`（628-642 行）末尾追加 `renderer.renderFrame(chart, preciseBeats, 4)` 与 `updateOverlayDom()`，并在全屏时同步 `updateFsPlayhead` 与 `fsTimeLabel.textContent`，恢复"拖动即看到对应帧"的能力。不直接调用 `renderAt`，因为 `renderAt` 内部会经 `updateSeekUi` 在 `isDragging` 时跳过 playhead 更新，这与拖动时由 `seekToPosition` 直接控制 playhead 的设计一致。
- `main.ts` `timelineHost` 的 `pointerdown`（644-652 行）追加 `e.preventDefault()`，防止触发 touch 默认行为干扰拖动事件序列。
- `main.ts` `document` 的 `pointermove`（654-660 行）改为按 `isFullscreen` 选择 `fsTimelineHost` 或 `timelineHost` 的 rect，使全屏拖动也能正确计算百分比。
- `main.ts` 新增 `document` 的 `pointercancel` 监听（672-676 行），系统中断时重置 `isDragging` 并调用 `renderAt(preciseBeats)` 停留在当前帧；不自动恢复播放，避免中断后突然发声。
- `main.ts` `fsTimelineHost` 的 `pointerdown`（1231-1241 行）补齐 `e.preventDefault()`、`isDragging=true`、`wasPlaying=isPlaying`、`if (isPlaying) pausePlayback()`，使全屏进度条可连续拖动。
- `index.html` `#fs-overlay` 样式块（189-204 行）追加 `touch-action: none`，避免全屏拖动时 WebView 触发默认滚动手势；`#fs-timeline-host` 已有该属性。
- 重新执行 `npm run build:chart-preview` 生成最新 `player.js` 与 `player.bundle`，哈希一致。

## 期望输出

- 非全屏拖动进度条时谱面实时变化，松手后若原本在播放则自动恢复播放。
- 全屏进度条可连续拖动，拖动期间谱面实时变化。
- 拖动被系统中断后，`isDragging` 立即重置，播放/暂停键点击不再被拖动逻辑干扰。
- 既有 lint、typecheck、Vitest、Jest 全部通过。

## 已知限制（本次不处理）

- **全屏方向反（Home 键在左）**：用户选择保持 `landscape_left` 以避免 Expo Go 下重新弹出 `[RNScreens] Unsupported orientation mask` 错误窗。若改回 `landscape_right`，方向正确但 Expo Go 下会反复弹窗。
- **状态栏错误**：Expo Go 是固定二进制，不读取 `app.json` 的 `infoPlist` 配置，`UIViewControllerBasedStatusBarAppearance=true` 在 Expo Go 中不生效。dev build / EAS build 中会写入 Info.plist，不会报错。`app.json` 已正确配置，无需代码修复。
- **全屏跳两下**：与原生方向应用时序、`visualViewport` resize 有关，需在 dev build 下实机调试。本次仅修复 JS 拖动 bug。
