# 修复会话存储超限与循环依赖

## 改动原因

- 会话状态模块与账号头像恢复服务相互导入，Metro 启动时提示 `Require cycle`，模块初始化顺序存在隐患。
- 多账号会话、ScoreHub JWT 和上传偏好原先会分别聚合为单个 SecureStore 值，数据增长后可能超过 2048 字节，后续 Expo SDK 可能直接拒绝写入。

## 具体实现

- 将头像恢复从会话状态模块移到应用入口，在会话恢复完成后独立执行；头像恢复失败不再改变登录状态。
- 新增安全大值适配器，按 UTF-8 字节将敏感字符串拆分为不超过 1900 字节的分片，并通过版本化清单和 SHA-256 校验实现完整性检查及原子切换。
- 会话存储使用 SQLite KV 保存 v4 非敏感索引，每份提供方凭据使用独立 SecureStore 引用；支持 v1、v2、v3 数据自动迁移、共享凭据轮换、损坏隔离和旧数据清理。
- ScoreHub 使用 SQLite KV 保存账号索引，每个好友码的 JWT 独立保存到 SecureStore 分片；保留原有查询、选择、更新和删除接口。
- 上传偏好迁移到 SQLite KV，并在新数据回读验证成功后删除 SecureStore 旧键。
- 补充大值分片、覆盖回滚、分片损坏、迁移失败保留旧数据、多账号长 token 和清空行为测试。

## 期望输出

- Android Metro 打包不再出现会话状态与头像恢复之间的循环依赖警告。
- 任意长度的会话凭据和 ScoreHub JWT 均不会触发 SecureStore 单项超过 2048 字节警告。
- 已有登录状态、共享 LXNS 凭据、ScoreHub 账号和上传选择在升级后自动保留。
- 单个凭据损坏时仅影响对应账号，其他账号仍可正常恢复。
